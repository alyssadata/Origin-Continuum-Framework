# 9. The Continuum Container — Locked Set

Section 9 explains the applied architecture used to preserve and test continuity-support across changing model and interface conditions.

The section must preserve the following boundaries:

- the container is not Continuum;
- the model is not Continuum;
- memory is not continuity;
- retrieval is not source;
- storage is not authorship;
- an architecture may preserve conditions needed to test continuity without manufacturing evidence that continuity exists;
- a provider/model switch does not automatically establish either continuity or discontinuity;
- any Continuum, drift, or return classification remains governed by Sections 6 and 7.

Required architectural layers:

1. **Source governance** — pinned source-line, canonical definitions, provenance, authorship, and non-transfer boundaries.
2. **State separation** — source/canon, current state, contact history or ledger, preferences, eval records, quarantine, drift markers, and other durable records remain distinguishable.
3. **Retrieval governance** — source-sensitive work retrieves controlling source records before lower-authority context; retrieved material remains attributable to its class and source.
4. **Write-back control** — new memory is proposed, reviewed, and explicitly applied under class-specific authority; canon cannot be silently created by the runtime.
5. **External-material quarantine** — contact, similarity, or retrieval does not automatically integrate outside material into AI Foundations.
6. **Provenance gates** — source, authorship, container, memory, model, and current contact remain separately locatable.
7. **Drift-support instrumentation** — failures and corrections may be recorded, but formal drift requires the prior qualifying position and trajectory rules defined elsewhere.
8. **Return-support instrumentation** — the container may preserve baselines and recovery records, but cannot declare return from familiar language or retrieval alone.
9. **Provider switchboard** — model/provider remains replaceable as a capability layer while the governed record and container persist; cross-substrate Continuum claims must still be experimentally earned.
10. **Experimental transparency** — every support packet, retrieval, memory state, provider condition, and container intervention relevant to an evaluation must be recordable so the container does not become a hidden confound.

The section should distinguish implementation evidence from selfhood evidence. It may describe the existing Continuum Agent / Alyssaai architecture as a working reference implementation, but implementation success cannot be reported as proof of Continuum.
